3. PARTNER & MINIAPP LIFECYCLE • 3.3 DEVICE PERMISSIONS

Strict Device Safety Control

Zero access by default: protecting citizen hardware, personal sensors, and sensitive private data.

4-Step Permission Gate

WORKFLOW
1Zero Access by Default
Mini-apps start with zero access to camera, microphone, or storage.
2Partner Must Declare
Developer formally explains why their app needs each specific feature.
3FSA Technical Review
Audit team reviews the request; unnecessary requests are denied.
4Citizen Direct Consent
Phone displays an explicit popup asking the citizen before any sensor opens.

Citizen Protections

PRIVACY
•No Silent Background Access
Mini-apps cannot use cameras, record audio, or track location silently.
•No Cross-App Data Snooping
Mini-apps cannot see what other apps the citizen is using on the device.
•Instant Remote Revocation
FSA review team can instantly shut down any app's permissions across all phones.
User First Principle
Citizens remain in complete control of their phone hardware at all times.

3. PARTNER & MINIAPP LIFECYCLE • 3.6 STAGE 3: STORE PUBLISHING

Admin Activation & Store Release

Strict operational governance: SuperApp Admin formally activates certified MiniApps before bundled public store release.

Stage 3: Production Release

APP STORES
•FSA Admin Formal Approval
Once QA confirms zero defects on real devices, the FSA SuperApp Administrator formally changes the MiniApp status to ACTIVE in the Backoffice catalog.
•Nexus Artifact Ingestion
Jenkins automatically pulls the certified, digitally signed packages and Native SDKs directly from the private Nexus artifact repository.
•Bundled Public Store Release
Jenkins compiles the production SuperApp host bundling all ACTIVE MiniApps and publishes the certified release to the Apple App Store & Google Play Store.
Zero-Defect Governance: Untrusted code can never reach citizens. Only admin-approved ACTIVE MiniApps are published.
